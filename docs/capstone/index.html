Ranking Content Refresh Opportunities from Prior Search Signals

Lane: Refresh / Content Opportunity Scoring · Author: Soyeb Ahmed · Date: 2026-11-01

Abstract. This study asks whether prior search and content signals can rank pages that are more likely to experience a decline in the next 30-day comparison window. I use the bundled 30,000-row anonymized FlyRank starter dataset and define the label as an impression decline of more than 20% in the latest 30 days versus the preceding 30 days. I compare a transparent rules baseline with logistic regression, a decision tree, and a random forest using only prior-window and static features under a client-holdout split. The random forest achieved ROC-AUC 0.870 and Precision@50 0.760, compared with 0.788 and 0.320 for the baseline. The resulting score is decision support for human review, not a prediction of Google's algorithm or a causal estimate of refresh impact.

1. Introduction / Problem statement

Content teams cannot manually inspect every page with equal priority. The operational decision is: which pseudonymized content items should a reviewer inspect first for a possible refresh? The model produces a ranked queue, reason codes, and suggested actions. A wrong high-priority call costs reviewer time; a missed opportunity can delay a useful content review.

2. Data

This run uses data/raw/content_refresh_anonymized.csv, the bundled starter slice with 30,000 rows and 44 raw columns. The source contains aggregated search/engagement measurements and content metadata with pseudonymized identifiers. No client names, domains, URLs, titles, raw queries, or credentials are used.

The label is trend_direction == "down": the latest 30-day impressions are more than 20% below the preceding 30-day impressions.

Scope note: This paper uses the bundled starter dataset because that is the data available in the supplied repo. It does not claim to have run on the gated ~79M-row warehouse release.

3. Methodology

The central leakage control is temporal. Because the label is defined by the latest 30-day period, the model excludes latest-window measurements and 90-day aggregates that include that period. It also excludes trend_direction, trend_pct, current freshness fields, and pseudonymous IDs. Features come from the preceding 30-day window plus static metadata; content age is shifted back 30 days to approximate the feature-time boundary.

The baseline is a transparent weighted score: 55% prior impressions, 25% prior sessions, 15% inverse word-count percentile, and 5% competition. Three models are compared: logistic regression, decision tree, and random forest. The random forest is selected by Precision@50 because the output is a ranked review queue.

Validation uses a fixed random seed of 42 and holds out approximately 20% of pseudonymized clients, keeping clients separated between train and test.

5. Limitations & honest framing

  • This run uses the 30,000-row starter dataset, not the gated full warehouse.
  • The label is an observed historical decline, not the effect of a content refresh.
  • Feature importance is association, not causation.
  • Client holdout is not the same as a future-calendar-time evaluation.
  • The score should be reviewed by a human and combined with editorial context.
  • The dataset does not contain page text, so the system cannot directly judge content quality.
  • Nothing here predicts or reverse-engineers Google's ranking algorithm.
